# 暗記アプリケーション

iPad と Apple Pencil で、**手書きで答えて自分で丸をつける**暗記アプリです。
選択肢や文字入力ではなく、実際に手で書いて覚えることを想定しています。

公開先: https://benkyouapuri.vercel.app/

---

## 0. 最初に読む — このリポジトリの位置づけ

**このリポジトリには問題データが1問も入っていません。**

| | 中身 | 場所 |
|---|---|---|
| **このリポジトリ** | アプリのコードだけ（HTML / CSS / JS / サーバー関数） | 公開してよい |
| **別の非公開リポジトリ** | 問題集・解答履歴 | 非公開。**この repo には含まれない** |

問題集は教科書などをもとに作るため、そのまま公開するわけにいきません。
そこで**置き場所ごと分けてあります。**このリポジトリを clone しても、
問題集は付いてきませんし、リポジトリを覗いても問題文は出てきません。

このリポジトリを読んで作業する人（および AI）への注意:

- `sets/` `index.json` `progress.json` を**このリポジトリに作らないでください。**
  それらは別の非公開リポジトリ側のファイルです（→ [6. ファイル形式](#6-ファイル形式)）
- 問題データを触る操作は、すべて `api/questions.js` 経由です。
  ブラウザ側のコードが GitHub を直接呼ぶことはありません
- 仕様に見えないものを「バグ」として直す前に、
  必ず [9. 直してはいけない仕様](#9-直してはいけない仕様) を確認してください。
  **意図的にそう作ってある箇所が複数あります**

### このアプリの目的（設計判断の基準）

> **スキマ時間に、空いている時間でいつでも始めたり終わらせたりでき、
> タイムパフォーマンスを最大化すること。**

出題は常に「いま最も価値の高い問題」から並びます。
そのため**途中でやめても、そこまでが最善**になります。

この目的から、以下は**採用しません。**

- 「今日のノルマ◯問」「連続◯日」といった、達成を求める設計
- 残り件数を大きく表示するなど、終わらせることを迫る表示

問題数が数万規模になったとき、自動で決まったノルマは達成不可能な量になりえます。
また「空いた時間だけやる」という前提と正面から衝突します。

## 1. 何をするアプリか

### 1回の学習の流れ

```
ホーム画面
  │  問題集を選ぶ → 「選択した問題集で開始」
  ▼
出題フェーズ … 画面全体に手書きで答える → 「決定」で次の問題へ
  │            （選ばれた問題を全部書き終えるまで続く）
  ▼
丸つけフェーズ … 模範解答と解説を見て ⭕️ / ❌ を自分で押す
  │
  ├─ ❌ があった → その問題だけを再び出題フェーズへ（正解するまで繰り返す）
  │
  └─ 全部 ⭕️ → 次のグループへ／なければホーム画面へ戻る
```

途中でやめたいときのために、出題フェーズ・丸つけフェーズには
**まとめて飛ばすボタン**があります。

### 主な機能

- **手書き解答** — 画面全体がキャンバス。Apple Pencil の 240Hz サンプリングをそのまま使います
- **パームリジェクション** — ペンを検知したら指の接触を無視します。
  ペンより先に手のひらが触れてしまった線も、ペンが触れた時点で取り消します
- **自己採点** — 正誤の判定は機械ではなく人間が行います
- **忘却曲線にもとづく出題順** — → [4. 出題アルゴリズム](#4-出題アルゴリズム)
- **出題する上限** — 「上位20問だけ」のように出題数を決められます
- **問題集の管理** — 階層フォルダとタグで整理し、複数の問題集をまとめて出題できます
- **iPad から問題集を追加** — CSV か JSON を貼り付けるかファイルを選ぶだけ。パソコンは不要です

## 2. データがどこにあるか

置き場所は4つあります。**どれがどこにあるかを取り違えないでください。**

| データ | 置き場所 | 消えるとどうなるか |
|---|---|---|
| アプリのコード | このリポジトリ → Vercel | 再デプロイで戻る |
| 問題集 (`sets/*.json`, `index.json`) | 非公開リポジトリ | 問題が失われる（Git 履歴から復旧可） |
| 解答履歴 (`progress.json`) | 非公開リポジトリ | 記憶予測が初期状態に戻る |
| 合言葉・歯車の設定・履歴の控え | ブラウザの localStorage | 合言葉を再入力すれば戻る |

localStorage に置いている鍵は次の3つです。

| キー | 中身 |
|---|---|
| `flashmemo_passphrase` | 合言葉（平文） |
| `flashmemo_memorySettings` | 歯車の中の設定 |
| `flashmemo_progress` | 解答履歴の控え。サーバーへ送る前に閉じても失わないため |

### 安全性の実際

- **GitHub のトークンは Vercel の環境変数にのみ存在し、ブラウザには一切渡りません。**
  問題データの読み書きは必ずサーバー関数 (`api/`) を通ります
- 問題集は Vercel のデプロイに含まれないため、公開URLから直接読み取ることはできません
- **守っているのは合言葉ひとつだけです。**合言葉が漏れれば、問題集は誰でも取り出せます。
  推測されにくい、十分に長いものにしてください
- 合言葉はブラウザに**平文で**保存されます。端末を他人が触れる状況では守れません

## 3. 使い方

### 3.1 合言葉を入れる

初回に一度だけ聞かれます。以後その端末では記憶されます（`flashmemo_passphrase`）。

### 3.2 問題集を追加する

ホーム画面の「問題集を追加」から、次を入力します。

| 項目 | 例 | 説明 |
|---|---|---|
| 保存先 | `世界史/近代/フランス革命` | **スラッシュがそのまま階層になります。**末尾がそのまま問題集の名前です |
| タグ | `世界史, 近代` | カンマ区切り。問題集ごとに付きます（省略可） |
| 問題 | 下記の CSV か JSON | 貼り付けるか、ファイルから読み込みます |

貼り付け欄・ファイルの中身が **`{` で始まっていれば JSON、それ以外は CSV** として読み取ります。
拡張子は見ません。**どちらと判定されたかはプレビューの先頭に `[JSON]` / `[CSV]` として常に出ます。**
判定がずれていないか、保存前にここで確認できます。

**ホーム画面に直接ファイルをドロップしても、この画面が開きます。**
中身が貼り付け欄へコピーされ、保存先はファイル名（拡張子を除く）が初期値になります。
**1つずつしか受け付けません。**保存先は1か所しか指定できないため、
まとめて複数落とすと、どのファイルをどこに保存すべきか決められないからです。

#### CSV の仕様

**1列目 = 問題、2列目 = 答え、3列目 = 解説（省略可）。**

```csv
ルイ16世,フランス革命期の国王,1793年に処刑された
バスティーユ牢獄,1789年7月14日に襲撃された,革命の発端とされる
```

カンマを含む文は二重引用符で囲みます。囲みの中では `""` が `"` 一文字になります。

```csv
"1789年7月14日,バスティーユ牢獄が襲撃された",フランス革命の発端
```

細かい挙動（つまずきやすい点）:

- **ヘッダー行は判別しません。**`問題,答え,解説` と書くとそれが1問として登録されます。書かないでください
- **4列目以降は無視されます**
- 各セルの前後の空白は取り除かれます
- **1列目か2列目が空の行は、警告なく捨てられます。**
  保存前にプレビューの問題数を確認してください
- 空行は無視されます

同じ保存先に問題集があるときは、上書きしてよいか確認されます。

#### JSON の仕様

**見出し（何を答える問題か）を鍵にした入れ子構造。** CSV と違い、
問題を出すときに「これは意味を聞かれているのか、類義語を聞かれているのか」を
問題文の中に残せます。

```json
{
  "次の英単語の意味を答えなさい。": {
    "banana": "バナナ",
    "cherry": "さくらんぼ"
  },
  "次の英単語の類義語を答えなさい。": {
    "look": "see"
  }
}
```

読み取りの規則は次の1つだけです。

> **値がオブジェクトならまだ見出し（さらに深く辿る）。
> 値が文字列か配列なら、そこが問題そのもの（鍵＝問題文の最後の断片、値＝答え）。**

この規則を再帰的に適用するだけなので、**見出しは何段でも重ねられます。**

```json
{
  "英単語": {
    "次の英単語の意味を答えなさい。": { "banana": "バナナ" },
    "次の英単語の類義語を答えなさい。": { "look": "see" }
  }
}
```

出題される問題文は、**通った見出しをすべて改行でつなげたもの**になります。
上の例なら `英単語\n次の英単語の意味を答えなさい。\nbanana` という3行になり、
単語だけでは判断できない「どちらの意味で答えるべきか」が常に画面に残ります。

解説を付けたいときは、値を `[答え, 解説]` の配列にします。

```json
{ "次の英単語の意味を答えなさい。": { "apple": ["りんご", "赤くて丸い果物"] } }
```

- 値が**文字列** → 答えだけ（解説なし）
- 値が**配列 `[答え, 解説]`** → 2つ目が解説

細かい挙動（つまずきやすい点）:

- 見出しと問題を**同じ階層に混ぜても**動きますが、見出しの意味が薄れるので避けてください
- JSON として壊れている場合（カンマの数が合わないなど）、保存はできず、
  プレビューにエラーの内容がそのまま表示されます

### 3.3 解く

ツリーから問題集を選び（複数可）、「選択した問題集で開始」を押します。
タグを選ぶと、**選んだタグをすべて持つ**問題集だけに絞り込まれます（AND 条件）。

ホーム画面には4つの設定があります。

| 設定 | 既定 | 意味 |
|---|---|---|
| 長期記憶（確率の低い順）優先選出 | ON | 忘却曲線で並べ替えます。OFF にすると問題集に入っている順のままです |
| 出題順をランダムにする | OFF | **選ばれた問題の中で、順番だけを入れ替えます。**どの問題が選ばれるかは変わりません |
| 問題と答えを逆にする | OFF | 2列目を問題として、1列目を答えとして出します |
| 出題する上限 | 0（全部） | 優先度の高い順に、この数だけ出題します |

> **「出題順をランダムにする」は、選出ではなく並び順だけを変えます。**
> 上限で切る**前**に混ぜてしまうと「優先度の高い問題を選ぶ」機能そのものが壊れます。
> この順序は v6.6.0 で意図的に直したものです（→ [4.3](#43-選出の順序変更禁止)）。
>
> なお「優先選出」を OFF にしたときだけは、選出そのものを無作為にします。
> 並べ替えの基準が何も無い状態で先頭から切ると、いつも同じ問題ばかりになるためです。

出題画面では画面のどこにでも書けます。「決定」を押すと次の問題へ進み、
選ばれた問題を全部書き終えると丸つけに移ります。

### 3.4 歯車の設定

一度決めたら普段は変えない値です。ブラウザに保存されます。

| 設定 | 既定 | 範囲 | 意味 |
|---|---|---|---|
| 正解したときの伸び | 2.5 倍 | 1.3〜4.0 | 正解すると記憶の寿命がこの倍率で延びます |
| 間違えたときに残す割合 | 20 % | 0〜60 | よく覚えていた問題ほど、間違えても間隔を長く保ちます |
| 間違えたときの最短間隔 | 30 分 | 5〜240 | 寿命がこれより短くなることはありません |
| 何問ずつに区切るか | 0（区切らない） | — | 長時間の勉強用 |

**「何問ずつに区切るか」について。**
これは**長時間の勉強専用**の設定です。0 のままなら、選ばれた問題は一続きで出ます。
たとえば 10 と入れると、100問が10問ずつのグループに分かれ、
グループごとに「出題 → 丸つけ → 間違えた分をやり直し」を繰り返します。
一続きで100問やるより、間違えた問題が早く戻ってきます。

スキマ時間に使うぶんには 0 のままで構いません。

## 4. 出題アルゴリズム

### 4.1 いま思い出せる確率

```
R = exp( -経過日数 / 記憶の寿命 )
```

- `経過日数` … 最後に解いてからの日数
- `記憶の寿命`（`lifespan`、単位は日）… 問題ごとに持つ値
- **一度も解いていない問題は `R = 0`** として最優先で出します

時間が経てば必ず下がるので、**どれだけ習熟した問題でも寿命を過ぎれば戻ってきます。**

> 以前は正解数を足し込む方式でしたが、熟達した問題の確率が頭打ちになり、
> 二度と出題されなくなる不具合がありました。v6.0.0 で忘却曲線に置き換えています。
> **正解数を確率の計算に使う方式へ戻さないでください。**

### 4.2 寿命の更新

自己採点で ⭕️ / ❌ を押したときだけ更新されます。

| | 新しい寿命 |
|---|---|
| ⭕️ 正解（2回目以降） | `max(前の寿命 × 伸び, 1日)` |
| ⭕️ 正解（その問題で初めて） | `1日` |
| ❌ 不正解 | `max(最短間隔, 前の寿命 × 残す割合)` |

同時に「最後に解いた日時」が現在時刻になります。

**間違えても寿命を 0 にはしません。**一度覚えたものは覚え直すのも速いので、
まっさらな新問題と同じ扱いにはしない、という判断です。
「すぐもう一度解かせる」役割は、その場の繰り返し（丸つけ後のやり直し）が担っています。
ここで決めているのは、**解き直した後に次はいつ出すか**です。

#### 同じセッションで2回目以降に解いた結果は記録しません

間違えた問題は、その場で必ずもう一度出題されます。
そこでの正解まで数えると、**数分間覚えていただけのものを長期記憶と誤認します。**
そのため記録するのは、そのセッションで**最初に答えた結果だけ**です
（`answeredThisSession` による制御）。

**これは意図的な仕様です。「間違えた問題を正解しても記録されない」を
バグとして直さないでください。**

### 4.3 選出の順序（変更禁止）

`script/quiz.js` の `startLearning()` は、必ずこの順で処理します。

```
1. 保存済みの解答履歴を、各問題に読み込む
      ↓   これを飛ばすと記憶予測が常に初期値になり、優先出題が無意味になる
2. 並べ替える
      優先選出 ON  → 思い出せる確率の低い順
      OFF かつランダム ON → 無作為
      ↓
3. 「出題する上限」で先頭から切る
      ↓   2 より前に切ると、優先度と無関係な問題が選ばれる
4. ランダム ON なら、切った後の中だけを混ぜる
      ↓   3 より前に混ぜると、優先度の高い問題を選ぶこと自体が壊れる
5. 「何問ずつに区切るか」でグループに分ける
```

**2 → 3 → 4 の順序は、それぞれ過去に実際のバグを起こして直したものです。
入れ替えないでください。**

## 5. 自分で動かす場合

Node.js もビルドも不要です。

### 5.1 このリポジトリを Vercel に接続する

[vercel.com](https://vercel.com) でこのリポジトリを import します。
フレームワークの指定は不要です（静的サイト + `api/` のサーバー関数として動きます）。

### 5.2 問題集用の非公開リポジトリを作る

GitHub で**新しい**リポジトリを **Private** で作成します。
このリポジトリとは別物です。README を1つ入れておいてください
（完全に空だと最初の書き込みに失敗します）。

### 5.3 トークンを作る

GitHub の Settings → Developer settings → Personal access tokens → **Fine-grained tokens**

- Repository access: **Only select repositories** → 5.2 で作ったリポジトリだけ
- Permissions → Repository permissions → **Contents: Read and write**

### 5.4 Vercel に環境変数を登録する

プロジェクトの Settings → Environment Variables に3つ登録します。

| Key | Type | 値 |
|---|---|---|
| `QUESTIONS_REPO` | Config | `ユーザー名/リポジトリ名`（5.2 のもの） |
| `GITHUB_TOKEN` | Secret | 5.3 のトークン |
| `APP_PASSPHRASE` | Secret | 自分で決めた合言葉 |

**登録しただけでは反映されません。再デプロイしてください。**

### 5.5 確認する

`https://<あなたのURL>/api/health` をブラウザで開きます。合言葉は不要です。

```json
{ "ok": true, "repo_set": true, "token_set": true, "passphrase_set": true,
  "github": { "reachable": true, "private": true }, "hint": null }
```

- `ok` が `false` のときは `hint` に原因が書かれています
- 合言葉なしで開いた場合、リポジトリ名などの詳しい情報は返しません。
  誰でも開ける状態でそれらを晒すと、攻撃の手がかりになるためです

## 6. ファイル形式

これらは**非公開リポジトリ側**のファイルです。このリポジトリには置きません。

```
sets/世界史/近代/フランス革命.json     問題集1つ
sets/英単語/システン/第1章.json
index.json                            問題集の一覧
progress.json                         解答履歴
```

### 問題集 `sets/<保存先>.json`

```json
{
  "title": "フランス革命",
  "path": "世界史/近代/フランス革命",
  "tags": ["世界史", "近代"],
  "updated_at": "2026-08-31T09:00:00.000Z",
  "questions": [
    {
      "id": "mfk3x1-0",
      "question": "ルイ16世",
      "answer": "フランス革命期の国王",
      "commentary": "1793年に処刑された"
    }
  ]
}
```

> **問題集のファイルに成績は入りません。**
> `question` の中に `correct_count` や `lifespan` を書いても、保存時に捨てられます
> （`api/questions.js` の POST が上記4項目だけを取り出すため）。
> 成績は `progress.json` にのみ存在します。**この分離を崩さないでください。**
> 問題集は書き換わらないので、問題文を編集しても成績は `id` で引き継がれます。

### 一覧 `index.json`

問題集の保存・削除のたびに自動更新されます。中身は各問題集の
`path` / `title` / `tags` / `count` / `updated_at` だけで、問題文は入りません。

### 解答履歴 `progress.json`

```json
{
  "updated_at": "2026-08-31T09:00:00.000Z",
  "stats": {
    "mfk3x1-0": {
      "correct": 3,
      "incorrect": 1,
      "lifespan": 6.25,
      "last_answered_at": "2026-08-31T08:59:00.000Z"
    }
  }
}
```

- キーは問題の `id`
- `lifespan` の単位は**日**
- 1問ごとに送るとコミットが膨大になるため、区切りでまとめて送ります
  （ホーム画面に戻ったとき／アプリが背面に回ったとき／60秒操作がないとき）
- 保存は**置き換えではなく合成**です。同じ問題については、
  `last_answered_at` が新しい方を採用します。複数の端末で使っても取りこぼしません

## 7. API

すべて `x-passphrase` ヘッダーでの合言葉が必要です（`/api/health` を除く）。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/questions` | 問題集の一覧（`index.json`） |
| GET | `/api/questions?path=世界史/近代/フランス革命` | 問題集1つの中身 |
| GET | `/api/questions?kind=progress` | 解答履歴 |
| GET | `/api/questions?rebuild=1` | リポジトリを走査して一覧を作り直す |
| POST | `/api/questions` | 問題集を保存（`{path, title, tags, questions, overwrite}`） |
| POST | `/api/questions` | 解答履歴を保存（`{kind:"progress", stats}`） |
| DELETE | `/api/questions?path=…` | 問題集を削除 |
| GET | `/api/health` | 設定の診断。合言葉なしでも開ける |

> **ブラウザのアドレス欄に貼っても動きません。**ヘッダーを付けられないため 401 になります。
> `curl` などを使ってください。

パソコンから直接ファイルを置いたなどで一覧がずれたときは、作り直せます。

```bash
curl -H "x-passphrase: あなたの合言葉" "https://benkyouapuri.vercel.app/api/questions?rebuild=1"
```

一覧を作り直す機能に画面上のボタンはありません。上のコマンドが唯一の入口です。

## 8. コードの構成

```
index.html          画面
style.css           フォントと最小限のスタイル

script/state.js     共有する状態
script/dom.js       HTML の要素への参照
script/util.js      小さな道具（CSV/JSON解析など）
script/memory.js    記憶モデル（忘却曲線と寿命の更新）
script/api.js       合言葉とサーバーとの通信
script/progress.js  解答履歴
script/canvas.js    手書きキャンバスとペンの設定
script/quiz.js      出題・採点・画面の切り替え
script/library.js   問題集の一覧とツリー
script/upload.js    問題集の追加
script/app.js       起動処理

api/questions.js    問題集の読み書き（合言葉が必要）
api/health.js       設定の診断
```

### 読み込み順に意味があります

ビルドは行わず、`index.html` が上の順番どおりに `<script>` で読み込みます。
モジュールではないので、**読み込んだ瞬間に上から実行されます。**

`state` → `dom` → 各機能 → `app` の並びは、次の理由で崩せません。

- `dom.js` は `document.getElementById` を**実行時に**呼ぶので、
  DOM より後（`</body>` 直前）に置く必要があります
- `memory.js` は読み込み時に `inputGroupSize` などへイベントを登録します。
  よって **`dom.js` より後**でなければ落ちます
- `app.js` の `window.onload` が全部の初期化を呼ぶので、**最後**に置きます

並べ替えるときは注意してください。

### バージョンの上げ方

読み込みは `script/xxx.js?v=x.y.z` の形にしています。
**変更したら、必ずバージョンを上げてください。**
忘れると iPad が古いファイルをキャッシュから読み、直したはずの不具合が再現します。

`index.html` の中で、バージョン文字列は **13 か所**に出てきます
（`style.css` に1、画面下部の表示に1、`script/*.js` に11）。
**全部を同じ値に揃えてください。**揃っているかは次で確認できます。

```bash
grep -o '6\.10\.0' index.html | wc -l
```

`13` 以外が出たら、揃っていません。

## 9. 直してはいけない仕様

**バグや未実装に見えますが、意図的にそう作ってあります。直さないでください。**

| 見え方 | 実際 |
|---|---|
| 画面切り替えのとき約1秒反応しない | 演出。`transitionPhase()` の 500ms + 500ms は仕様 |
| 進捗バーの黄色と緑が同じ幅に見える | デザイン。黄色は必ず緑以上の長さになるので問題ない |
| 手書きに「元に戻す（1画取り消し）」がない | 不要と判断済み。全消しだけでよい |
| 画面を回転させると手書きが歪む | そのままでよい |
| `h-screen` (100vh) を使っている | 「ホーム画面に追加」でツールバー無しの専用ウィンドウとして開くため問題にならない |
| 間違えた問題を正解しても成績が増えない | 意図的（→ [4.2](#同じセッションで2回目以降に解いた結果は記録しません)） |
| 全問正解した後、グループ全体を解き直さない | v6.4.0 で意図的に廃止。**戻さないこと** |

**出題フェーズと丸つけフェーズのデザインは確定済みです。見た目を変更しないでください。**
ホーム画面・問題集追加画面・設定画面は変更してかまいません。

新しい機能を提案する前に、[0. の目的](#このアプリの目的設計判断の基準)を確認してください。
ノルマ型・達成型の設計は、このアプリの目的と衝突します。

## 10. 開発時の注意

ローカルで動かす場合は、任意の静的サーバーで十分です。

```bash
python -m http.server 5173
```

ただし、ローカルの静的サーバーには**2つの制約があります。**

**① `api/` のサーバー関数は動きません。**
問題集の読み書き・解答履歴の保存は、すべて失敗します。
画面の見た目やレイアウトの確認にしか使えません。

**② `getCoalescedEvents()` は HTTPS でないと使えません。**
これはブラウザが「安全なコンテキスト」でしか許可しない API です。
`http://` では Apple Pencil の 240Hz が取得できず、**60Hz 相当に落ちます。**

実測値:

| 経路 | 取得できた点の数 |
|---|---|
| `http://` （ローカル） | 61.2 点/秒 |
| `https://` （Vercel） | 239.7 点/秒 |

**書き心地の検証は必ず HTTPS で行ってください。**
`http://` で「線がかくかくする」と感じても、それはコードの問題ではありません。
