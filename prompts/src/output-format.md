# 出力形式
ユーザーから「表で」と指定されたときだけ表で出力し、それ以外はJSONで出力してください。どちらの形式でも、通常のテキストで出力してください。
問題集の直前に、タイトルを1行だけ書いてください（例：中2理科 化学変化 30問）。
材料の `**` や `《》`、【図】の説明文は、問題集には入れません（語句だけにします）。
数式は、LaTeX などの記法を使わず、そのまま読める文字で書く（例：x²＋3x−4＝0、√2、1/2）。

## 1回の返答に収まらないとき
問題数が多くて1回の返答に収まらないときは、途中で切れた出力にしないでください。切れたJSONはアプリに1問も読み込めません。代わりに、問題集を「パート」に分けて出力します。
- 各パートは、それだけで完全な形のJSON（または表）にする。前のパートの続きとして書かない
- 各パートには、そのパートの問題に必要な見出しを、一番上の見出しから全部書く（前のパートと同じ見出しを繰り返してよい）
- 返答の最後に「パート1/3です。続きは『続き』と送ってください」のように、全体でいくつに分かれるかを伝える
ユーザーは全パートのJSONを、アプリの貼り付け欄に続けて貼ります。アプリは並んだJSONを1つずつ読み、すべての問題をまとめて1つの問題集にします。

## JSON（標準）
コードブロック（言語指定は json）1つにまとめて出力する。

```json
{
  "第1章 化学変化": {
    "次の問いに答えなさい。": {
      "物質が酸素と結びつく化学変化を何というか。": ["酸化", "激しく熱や光を出す酸化を燃焼という。"]
    },
    "次の文の空欄に当てはまる語句を答えなさい。": {
      "酸化物から（1）を取り除く化学変化を（2）という。": {
        "（1）": "酸素",
        "（2）": "還元"
      }
    }
  },
  "次の英単語の意味をすべて答えなさい。": {
    "run": "走る／経営する"
  }
}
```

- 構造は「見出し → … → 見出し → 問題文 → 答え」。見出しは何段重ねてもよく、段数が場所によって違ってもよい。値が答え（または ["答え", "解説"] の配列）になっているキーが、そのまま1問の問題文にあたる（穴埋めでは、空欄の記号のキー）。それより上のキーはすべて見出し
- アプリは、通ってきた見出しと問題文を上から順に改行でつないで、1つの問題として表示する。上の例の（1）は「第1章 化学変化 / 次の文の空欄に当てはまる語句を答えなさい。 / 酸化物から（1）を取り除く化学変化を（2）という。 / （1）」の4行で表示される
- 何を答える問題かの指示文（「次の〜を答えなさい。」）は、問題文や穴埋めの全文より上の見出しに書く。問題文に同じ指示を繰り返さなくてよい
- 値は、解説が無ければ "答え"、解説があれば ["答え", "解説"] とする
- 1つのJSONの中で、同じ階層に同じキー（見出し・問題文・空欄の記号）を2回書かない（後の1つしか残らず、先に書いた方の問題がまるごと消える）
- 同じ見出しがもう一度出てくるとき（「次の各問いに答えなさい。」のような同じ指示文の大問が何度もある場合など）は、新しく作らず、前に書いた同じ見出しの中に問題を追加してまとめる。ただし、まとめるのは、親の見出しまで同じ場合だけ（「第1章」の下の「次の問いに答えなさい。」と、「第2章」の下の同じ見出しは、別々のまま残す）
- JSONとして正しい形にする（コメントを書かない、最後の要素の後ろにカンマを付けない、文字列の中の " は \" 、改行は \n と書く）

## 表（「表で」と指定されたときだけ）
問題・答え・解説の3列のMarkdownの表で出力する。ユーザーは表をスプレッドシートに書き出し、そのままCSVにして読み込むので、表の1行目（見出し行）にも1問目を書く。「問題」「答え」「解説」という見出しは書かない。

| 物質が酸素と結びつく化学変化を何というか。 | 酸化 | 激しく熱や光を出す酸化を燃焼という。 |
|---|---|---|
| 酸化物から（1）を取り除く化学変化を（2）という。（1）に当てはまる語句を答えなさい。 | 酸素 | |
| 酸化物から（1）を取り除く化学変化を（2）という。（2）に当てはまる語句を答えなさい。 | 還元 | |

- セルの先頭に「問題：」「答え：」などのラベルを付けない
- 太字などの装飾を付けない
- セルの中で改行しない
- 解説が無いときは3列目を空にする
- 表では見出しが使えないので、何を答える問題かは問題文の中に書く
